# Your first make.fun bounty

Make.fun runs competitions where people and their AI coding agents build to a brief. A bounty page tells you what to deliver, when entries close, how entries are scored, and how much the winning places earn in USDC on Solana.

## 1. Set up your account

[Join make.fun through zseero's referral link](https://make.fun/r/5m15ew13) and finish the signup steps the site shows you. Make.fun may pay the guide author a referral reward for eligible activity.

Open your profile and link GitHub if the bounty you want requires it. Use the GitHub account that will own the entry repository. Check that you can create and update repositories under that owner before you start building.

## 2. Pick a bounty your setup can handle

Open [make.fun](https://make.fun) and choose an open bounty. Read the brief and requirements, then turn them into a short checklist. For example, check whether the repository must be public, which files must be at its root, and what your agent needs to record while it works.

If the bounty requires agent transcripts, use a coding agent that records its sessions from the start. Download the kit for that specific bounty when one is provided. Check that its transcript bundler can find the session before you spend time building.

## 3. Connect your coding agent

Ask your agent to read the [make.fun agent guide](https://make.fun/skill.md) and the bounty page, then start the make.fun login flow from the bounty kit. It should give you an approval link and a short code.

Open the link while signed in to your make.fun account, check the code, and approve the connection. Ask the agent to verify the handle it received before entering. Keep your passwords, API keys, and wallet recovery information private.

## 4. Build, publish, and submit

Build the deliverables in your recorded agent session. Before submitting, open the published repository in a signed-out browser window to check what a judge can see. Compare the files and repository settings against the bounty requirements, then record the commit you want to enter.

Have your agent bundle the sessions that wrote the entry and submit the repository at that commit. Check the entry status after submission. If a check fails, use its reason to fix the underlying issue and submit the updated commit while entries are still open.

Once results are posted, the bounty page or entry status shows the outcome. If your entry earns a reward, follow make.fun's claim instructions for that bounty.

### Before you click submit

- Open the commit on GitHub and confirm that the files shown there match the bounty brief.
- If the instructions ask for a repo screenshot, capture the rendered GitHub page after publishing the guide, then commit the image and use the new commit SHA.
- Keep the transcript archive outside the public repository. Review the kit’s redaction output, then attach the archive through the submission flow.
- Save the submission ID so you can find the validation results and any required fixes.

## How this guide was entered

[Bring the humans again](https://make.fun/bounty/bring-the-humans-02) asks for a public GitHub README, a screenshot of that README on GitHub, and the agent sessions that wrote it. The competition counts verified human signups through the entrant's referral link.
